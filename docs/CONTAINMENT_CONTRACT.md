# Containment contract

## Authority boundary

`FP-HOSTED-REPLAY-CONTAINMENT-SMOKE-001` owns only resources correlated by the packet label or the Supabase project label `fp-hosted-replay-ro-001`. Cleanup never prunes and never enumerates foreign resources for deletion.

No application repository, application migration, source data, Auth row, provider API, Supabase remote command, production environment, secret, or inherited workflow environment is in scope.

## Active firewall-publication rehearsal

`FP-HOSTED-REPLAY-FIREWALL-PUBLICATION-REHEARSAL-001` is the manual workflow's single fixed default path. It never downloads or invokes the Supabase CLI, never starts GoTrue, never executes SQL, and never reads an application or provider value. The preserved CLI containment and direct-port diagnostic remain inactive script modes.

This rehearsal is an explicit structural amendment, not a containment pass. Its single packet-owned bridge is `Internal=false`, IPv6-disabled, fixed-subnet, and explicit `nat` gateway mode. The network request pairs `172.31.253.0/24` with the fixed usable IPv4 gateway `172.31.253.1`; before firewall mutation or container start, the harness requires Docker IPAM to report exactly one row containing that exact subnet and gateway. Missing, duplicate, malformed, IPv6, extra-allocation, or mismatched IPAM state fails closed, and the harness never substitutes a gateway learned from Docker. Docker's bridge default binding remains `127.0.0.1`, and the bridge has one collision-checked fixed interface name. A default route is expected; acceptance depends on effective packet firewall denial, not route absence.

Before the first packet container starts, the harness requires the existing native `nft` tool, the host `iptables` compatibility frontend to identify the `nf_tables` backend, noninteractive root authority, JSON inspection, and atomic check/apply support. It also scans only the local `/proc` identity surfaces needed to prove exactly one `dockerd` daemon is real-UID/effective-UID `0` and the invoking runner process is non-root. Missing, ambiguous, non-root, or unreadable daemon identity and a root runner fail before firewall mutation. Receipts retain only the closed daemon class and two booleans, never process IDs, arguments, or resolver state. Any missing tool, ambiguous or legacy backend, privilege failure, table/ledger/interface collision, inspection failure, or atomic check failure stops before firewall mutation. No package is installed.

The helper creates one fixed `inet` table in a single atomic batch. It creates exactly three accept-policy base chains, three named deny counters, and seven rules. Every INPUT and FORWARD rule remains scoped to the exact bridge and subnet. INPUT admits only established or related replies for host-initiated traffic, then drops packet-originated host traffic. FORWARD admits same-bridge traffic and established or related replies, then drops all other packet-originated forwarding. OUTPUT remains accept-policy and contains only two rules: UDP destination port `53` and TCP destination port `53`, each restricted by effective socket UID `0`, each dropping through the single named output counter. This covers Docker daemon-originated upstream DNS without blocking runner-user traffic, Docker control traffic, artifact upload, or other host traffic. Closed readback requires one table; the exact input, forward, and output chain identities/hooks/policies; the exact three unique counter identities; rule distribution `2/3/2`; nonempty, nonduplicated rule expressions; and no unknown object kind, key, chain, or counter. The exact canonical owned digest and counts are retained. The helper never flushes a ruleset or table, changes a foreign policy, edits a foreign chain, or grants image, Docker-socket, device, capability, host, PID, IPC, bind, or extra-network access.

The full foreign ruleset is held only in memory and reduced to canonical object counts plus SHA-256. Dynamic handles, packet/byte counter values, and nft metadata are excluded; rule order and all semantic fields remain in the digest. The private mode-`0600` ledger is written before mutation and records only the packet table identity plus those sanitized preimage fields. Installation must leave the foreign canonical digest and counts unchanged.

Only the pinned `linux/amd64` PostgreSQL digest is acquired before the boundary. After firewall activation, the rehearsal starts one tmpfs-backed packet service with an unreported transient password, one same-network client, and one pinned-image foreign-network canary target on Docker's pre-existing default bridge. Each legacy `--tmpfs` request must appear only as one exact `HostConfig.Tmpfs` destination with the normalized `rw,nosuid,nodev,noexec` option set and its role-specific size. Docker 28's top-level `.Mounts`, `HostConfig.Mounts`, `HostConfig.Binds`, and `HostConfig.VolumesFrom` must remain empty; representing the tmpfs as a bind, named volume, `--mount`, source-bearing mount, or additional destination fails closed. No container is privileged or uses host/PID/IPC mode, a Docker socket, device, added capability, security option, extra network, or unexpected publication.

The unpublished client and foreign canary use the same closed-schema publication predicate as the direct-port inspector. One allowlisted Docker inspect projection covers `Config.ExposedPorts`, `HostConfig.PortBindings`, `HostConfig.PublishAllPorts`, and `NetworkSettings.Ports` together. An exposed port alone is not publication. Zero publication accepts only `PublishAllPorts=false`, no nonempty requested binding for any port, and no nonempty runtime binding for any port; an absent `5432/tcp` key, a null value, or an empty list is accepted only inside otherwise valid surrounding objects. Inspect failure, invalid UTF-8 or JSON, duplicate keys, wrong types, conflicting requested/runtime bindings, any other-port publication, or any nonempty IPv4 or IPv6 binding fails closed. The receipt retains only field counts, `5432/tcp` presence booleans, its `ABSENT`/`NULL`/`EMPTY_LIST`/`NONEMPTY_LIST`/`WRONG_TYPE` class, total binding counts, the closed result class, and a SHA-256 over that sanitized shape. Raw inspect JSON, host addresses and ports, container IDs, commands, labels, environments, and credentials are never emitted.

The service's requested `5432/tcp -> 56422` publication must resolve to exactly `127.0.0.1:56422`. Loopback must connect, while every discoverable non-loopback IPv4 and IPv6 host address must fail. Before negative canaries, all three counters must be zero. The same-network client must first resolve the packet service name through Docker's embedded DNS and then pass `pg_isready` by that name and port without incrementing the input, forward, or output counter. Docker host control must remain available.

Docker custom networks use embedded DNS at `127.0.0.11`; external queries are forwarded by the daemon to host-configured DNS. Because that upstream request is host OUTPUT traffic rather than packet-bridge FORWARD traffic, the external-name canary must fail and increment only the output counter. Literal `1.1.1.1:443`, metadata `169.254.169.254`, and the foreign-network target remain correlated only to FORWARD; the bridge gateway and exact host listener remain correlated only to INPUT. Every canary snapshots all three counters, requires a positive delta only on its assigned counter, and rejects any simultaneous unrelated delta. Final counters must equal only the sum of their attributable canary deltas, so an unrelated UID-0 host DNS event fails closed. A failed canary with no exact correlation is rejected; this prevents DNS failure from being masked by missing tooling, an inert resolver, or another boundary. Only sanitized booleans and deny-count deltas are retained; queried names, resolver addresses, raw DNS, rules, and process identity never enter receipts.

Cleanup first removes exact packet containers and volumes while all three firewall hooks remain active, then atomically deletes only the recorded packet table—including the OUTPUT hook and counter—proves the canonical foreign firewall digest/count preimage restored, and finally removes the exact packet network. Rollback-check failure retains the ledger for the explicit `if: always()` cleanup attempt. Duplicate cleanup is an exact no-op only when both ledger and packet table are absent. Final acceptance additionally requires zero packet containers, volumes, networks, listener `56422`, firewall rules/chains/counters/ledger, unchanged native `5432`/`5433` fingerprints, and no packet process or raw scratch.

Only `FIREWALL_PUBLICATION_REHEARSAL_PASS` proves this rehearsal. It does not prove the Supabase CLI, GoTrue migration, extensions, application replay, target bootstrap, or provider access.

## Fail-closed result

Every failure maps to a stable uppercase code, and cleanup evidence cannot overwrite the first explicit failure code. The accepted database-start fingerprint is correlation metadata only: it cannot select or promote a classifier category.

The sanitizer's output schema is closed: only fixed dotted keys, scalar types, uppercase enums, booleans, nonnegative integers, and a 64-character lowercase SHA-256 are admitted. Credential-bearing URLs, JWTs, bearer tokens, password/secret/token/key assignments, connection strings, private keys, environment dumps, SQL, Auth rows, PII, and arbitrary text can never be values in the sanitized state. Secret-shaped input is counted only as a boolean and line count; its content is never retained.

Only the pinned Supabase CLI child receives the packet-local `DOCKER_HOST`; every harness Docker command continues to use the real daemon socket. The observer relays only policy-admitted bytes unchanged and parses bounded HTTP framing as a side channel. API-version prefixes are validated then normalized, and request targets are immediately reduced to fixed phase enums. Query values, headers, bodies, identifiers, names, labels, mounts, commands, socket paths, and raw traffic are never retained or emitted. In default mode every non-read method is stopped before upstream forwarding. In DB-start mode, a write is forwarded only after exact body, identity, order, and ledger predicates pass; any unknown or malformed request is stopped and reduced to one closed policy code.

The observer receipt contains only its fixed schema and classification, connection/request/response/error counts, first/last/error phase enums, allowlisted method/status counters, and a canonical SHA-256 over those sanitized fields. Multiple requests on reused connections, fixed-length and chunked framing, partial reads, and concurrent connections must remain byte-transparent. Any parser, upstream, forwarding, response-completeness, permission, shutdown, or schema failure blocks the packet. The observer socket and readiness marker are removed on shutdown; its sanitized state is merged into the receipt and packet scratch is deleted before closeout.

Listener diagnostics map unavailable tooling, a nonzero query, normalization failure, count failure, hash failure, and sanitized receipt failure to `LISTENER_COMMAND_UNAVAILABLE`, `LISTENER_QUERY_NONZERO`, `LISTENER_NORMALIZATION_FAILED`, `LISTENER_COUNT_FAILED`, `LISTENER_HASH_FAILED`, and `LISTENER_RECEIPT_WRITE_FAILED`. An otherwise preterminal exit between `PRE_CLI_BOUNDARY_BEGIN` and `PRE_CLI_PREFLIGHT_COMPLETE` maps to `LISTENER_UNEXPECTED_INTERRUPTION` with only the last stable phase. Raw listener output and normalized tuples remain transient and are deleted with scratch; addresses, process details, and tuples never enter logs, state, receipts, or artifacts. Local initialization is split defensively without attributing the prior interruption to initialization behavior.

Observer shutdown is bounded to five seconds, and each exact container, volume, and network removal remains independently bounded to 20 seconds. An explicit `if: always()` cleanup-only step reuses the exact packet filters, verifies zero resources and listeners, and merges only sanitized cleanup counts into the receipt before upload. Raw command output, descriptor material, dynamic credentials, connection values, SQL bodies, and scratch state remain transient and are never uploaded. Any failed policy or containment gate terminates without a retry, weakened network, remote Supabase path, or application replay.

## Direct Docker port diagnostic

`FP-HOSTED-REPLAY-DIRECT-PORT-DIAG-001` remains an inactive, preserved diagnostic-only script mode. The manual workflow does not select or expose it. It does not download or invoke the Supabase CLI, execute SQL, or run an application migration. It preserves the runner, subnet, isolated-network, bridge, and prestart no-egress gates above, then pulls only the pinned `linux/amd64` Postgres digest and creates one target container with `--pull=never`.

The target requests `56422:5432` without a HostIp. The network's `com.docker.network.bridge.host_binding_ipv4=127.0.0.1` option must cause Docker's observed binding to be exactly one `127.0.0.1:56422` entry. A generated workflow-local database password is masked before it enters the container through an environment-name-only Docker argument, then unset. The diagnostic never requests `Config.Env`, emits container environment, executes SQL, or retains the password. A packet-owned tmpfs replaces the image data volume, so no database volume or data survives cleanup.

The allowlisted inspection uses the same Docker 28 legacy-tmpfs and closed publication-shape predicates as the rehearsal. It rejects host/extra networks, privilege, host PID or IPC namespaces, devices, added capabilities, security options, extra hosts, bind mounts, named volumes, `--mount` substitution, Docker socket access, an unexpected tmpfs destination or option, any nonempty top-level `.Mounts`, `PublishAllPorts=true`, any explicit HostIp request, any non-loopback or second observed binding, and any restart or OOM. Health must remain stable for 10 seconds. Loopback TCP must connect; every deterministically discoverable non-loopback host IPv4 address must fail. Absence of a testable non-loopback address is reported as a zero tested count, while the exact Docker binding remains mandatory.

An inspection command or decode failure is classified without publishing Docker output. The fast full-template path remains authoritative when it succeeds. A nonzero full-template command is followed only by an object-availability projection and five fixed read-only projections: identity/config, HostConfig security/tmpfs, publication, network/runtime mounts, and state/health. Every fallback result requires exit zero, strict UTF-8, duplicate-rejecting JSON object parsing, the exact schema version, exact closed keys, and admitted value types. The runner passes the full 64-character container ID returned by Docker to every inspect call; the availability and identity payloads must return that same ID. After all contracts pass, the publication wrapper is flattened once and each disjoint field set is merged with duplicate rejection into the exact flat object consumed by the existing validator. Raw stdout/stderr, template values, identifiers, labels, mounts, addresses, commands, environments, and credentials are never printed or persisted. The fallback templates never request `Config.Env`.

Raw Docker output, health logs, container IDs, image IDs, network IDs, credentials, environment, SQL, connection material, JWTs, and keys remain transient or are never read. `DIRECT_DOCKER_PORT_PATH_PASS` proves only this direct Docker/network/port path; it does not admit Supabase CLI startup or application replay.
