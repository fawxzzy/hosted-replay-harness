Health must remain stable for 10 seconds. Loopback TCP must connect; every deterministically discoverable non-loopback host IPv4 address must fail. An inspection command or decode failure is classified without publishing Docker output. The fast full-template path remains authoritative when it succeeds. A nonzero full-template command is followed only by an object-availability projection and five fixed read-only projections: identity/config, HostConfig security/tmpfs, publication, network/runtime mounts, and state/health. Every fallback result requires exit zero, strict UTF-8, duplicate-rejecting JSON object parsing, the exact schema version, exact closed keys, and admitted value types. The runner passes the full 64-character container ID returned by Docker to every inspect call; the availability and identity payloads must return that same ID. Because an exact immutable object ID is used rather than a mutable name or prefix, removal makes a later call fail and a different object cannot satisfy correlation. After all contracts pass, the publication wrapper is flattened once and each disjoint field set is merged with duplicate rejection into the exact flat object consumed by the existing validator. Any object, group, schema, identity, merge, or parse disagreement remains a closed `DIRECT_INSPECT_*` failure; successful composition continues through the unchanged network, tmpfs, publication, privilege, health, and loopback checks.

On failure, the diagnostic retains only its attempt number, exit class/code, stdout/stderr byte and line counts and SHA-256 digests, UTF-8 status, strict JSON parse class, first failed fixed field group, successful-group count, and a canonical diagnostic digest. Raw stdout/stderr, template values, identifiers, labels, mounts, addresses, commands, environments, and credentials are never printed or persisted. The fallback templates never request `Config.Env`.

Only `fawxzzy.hosted-replay-harness.direct-port-result.v1` is publishable for this mode. Its allowlist is packet, terminal status/failure code, hashed image/network/container identities, binding class/counts, health/restart/OOM state, timings, and cleanup counts. Raw Docker output, health logs, container IDs, image IDs, network IDs, credentials, environment, SQL, connection material, JWTs, and keys remain transient or are never read. `DIRECT_DOCKER_PORT_PATH_PASS` proves only this direct Docker/network/port path; it does not admit Supabase CLI startup or application replay.
